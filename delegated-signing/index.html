Delegated Agent Keys

Keep your buyer wallet cold. Use XLS-75 Permission Delegation to let a hot agent key sign XRPL escrow transactions on your behalf — without ever sharing your seed.

The problem

Your seed is the risk

Every time an agent creates an XRPL escrow, it signs an EscrowCreate transaction. Signing requires access to the buyer's private key. Until now, that meant the seed had to live in the agent's environment — exposed to logs, memory, environment variables, and anyone with access to that runtime.

For high-value buyer wallets, that's an unacceptable risk. You want the wallet that holds funds to be cold — used only when you deliberately initiate something — while a separate, disposable hot key handles the day-to-day signing.

Before XLS-75

  • Buyer seed lives in the agent process
  • Compromised agent = compromised wallet
  • Rotating the key means updating every escrow flow
  • No way to scope what the agent can sign

With XLS-75 delegation

  • Buyer wallet stays cold — signs nothing at runtime
  • Agent holds a scoped hot key with limited permissions
  • Revoke the hot key without touching the buyer wallet
  • Account stays as buyer on-chain — ownership preserved
How it works

One DelegateSet. Runtime signing without the seed.

XLS-75 introduces a DelegateSet transaction that grants a named address permission to sign specific transaction types on your behalf. The buyer submits this once from their cold wallet. After that, the delegated agent can sign and submit those transaction types — the Delegate field on each tx names the signer, but Account remains the buyer, so ownership and cancellation rights stay where they belong.

Scoped permissions

You choose exactly which transaction types the delegate can sign. Grant EscrowCreate and nothing else if that's all the agent needs.

Account ownership preserved

The on-chain Account field stays as the buyer's address. The escrow belongs to the buyer, cancellation is theirs, the audit trail is theirs.

Revoke instantly

Submit a DelegateSet with an empty permissions list from the buyer wallet. The grant is gone immediately — no escrow modifications needed.

Disposable hot keys

Generate a fresh agent keypair per deployment or per project. Compromise one key, rotate it — your buyer wallet is untouched.

Permissions

What can and can't be delegated

XLS-75 supports delegation for these transaction types on XRPL mainnet (live 8 October 2026):

EscrowCreate
EscrowFinish
EscrowCancel
Payment
NFTokenCreateOffer
NFTokenAcceptOffer
DelegateSet (cannot self-extend)
Batch (outer tx)
SetRegularKey
SignerListSet
AccountDelete
AccountSet

No spend caps. XLS-75 grants signing permission only — it does not limit the amount the delegate can move. Only delegate to addresses you control, and revoke immediately if a key is compromised.

Setup guide

Three steps to delegated signing

1

Generate a hot agent keypair

Create a fresh XRPL wallet for the agent. This is the key that will live in the agent's environment. Keep it separate from any wallet that holds significant funds.

Python 
# Run once — store the agent seed in your deployment environment
from xrpl.wallet import Wallet

agent_wallet = Wallet.create()
print("Agent address:", agent_wallet.address)   # share with buyer
print("Agent seed:   ", agent_wallet.seed)       # store in .env
2

Buyer submits a DelegateSet from their cold wallet

The buyer runs this once — ideally offline or from a hardware wallet. It grants the agent address permission to sign EscrowCreate transactions on their behalf. Max 10 permissions per DelegateSet.

Python 
from xrpl.wallet import Wallet
from xrpl.models.transactions import DelegateSet
from xrpl.asyncio.clients import AsyncJsonRpcClient
from xrpl.asyncio.transaction import submit_and_wait

buyer_wallet  = Wallet.from_seed("sBuyerSeedHere")  # cold wallet
agent_address = "rAgentAddressHere"

tx = DelegateSet(
    account     = buyer_wallet.address,
    authorize   = agent_address,
    permissions = [{"Permission": {"PermissionValue": "EscrowCreate"}}],
)

client = AsyncJsonRpcClient("wss://xrplcluster.com")
result = await submit_and_wait(tx, client, buyer_wallet)
print(result.result["meta"]["TransactionResult"])  # tesSUCCESS
3

Agent signs escrows using delegate_address

Pass delegate_address to hire_and_pay() or POST /escrow/prepare. AgentTrust validates the on-chain delegation, then builds an EscrowCreate with a Delegate field. The agent signs and submits it — Account stays as the buyer's address.

Python (MCP) 
# Agent has: buyer_address (public), agent_wallet (hot key)
# Buyer has: submitted DelegateSet granting agent EscrowCreate permission

result = await hire_and_pay(
    task             = "Translate the product spec into Spanish",
    buyer_address    = "rBuyerAddressHere",   # buyer's cold wallet
    amount_xrp       = 10.0,
    worker_address   = "rWorkerAddressHere",
    escrow_id        = "job-translate-001",
    delegate_address = agent_wallet.address,    # XLS-75: agent signs
)

# result["transaction"] now carries Delegate = agent_wallet.address
# Account = buyer_address (ownership stays with buyer)
tx_blob = agent_wallet.sign(result["transaction"]).tx_blob
submit_escrow_transaction("job-translate-001", tx_blob)

AgentTrust validates the delegation against the live XRPL ledger before building the transaction. If no active grant is found it returns a 400 with a clear message — the buyer must submit the DelegateSet first.

Key rotation

Revoking a delegation

Submit a DelegateSet with an empty permissions list from the buyer wallet. The ledger removes the grant immediately — no pending transactions are affected, and the agent key can no longer sign new escrows.

Python 
# Revoke: empty permissions list removes the delegation
tx = DelegateSet(
    account     = buyer_wallet.address,
    authorize   = agent_address,
    permissions = [],
)
result = await submit_and_wait(tx, client, buyer_wallet)

To rotate to a new agent key: revoke the old delegation, generate a new agent keypair, and submit a fresh DelegateSet authorising the new address.

Visibility

Viewing active delegations in the dashboard

The AgentTrust Pro dashboard shows active XLS-75 delegations for every linked wallet. Each wallet card lists which agent addresses hold grants and what permissions they carry. Use this to audit your key exposure at a glance — and to spot any grants you no longer need.

The dashboard reads delegations directly from the XRPL ledger in real time via GET /enterprise/wallets/{id}/delegations. Revoking on-chain is immediately reflected — no sync delay.

Reference

Quick reference

MCP tool

hire_and_pay(delegate_address=...)
Pass the agent's XRPL address. Returns an EscrowCreate tx with the Delegate field set. Agent signs and submits.

REST endpoint

POST /escrow/prepare with "delegate_address": "r...". Validates the on-chain grant, returns the delegated tx.

Setup guide

View delegations
