Guides

Automated invoice verification

Lock payment in escrow when you raise a purchase order. The supplier submits their invoice and an AI referee checks it matches before releasing payment — no AP team required.

The problem

Accounts payable is slow, expensive, and fraud-prone

Without AgentTrust
  • Invoice arrives, sits in an AP queue for days
  • Human manually checks it against the PO
  • Approval chain adds more delays
  • Payment goes out — sometimes to the wrong account
  • Duplicate invoice fraud costs businesses billions annually
With AgentTrust
  • Payment locked in escrow at PO creation
  • Supplier submits invoice via API or webhook
  • AI referee verifies it against the PO spec instantly
  • PASS → payment releases on-chain automatically
  • FAIL → supplier corrects and resubmits

Works for any buyer–supplier relationship: agencies billing clients, freelancers submitting invoices, SaaS companies charging for usage, or supply chain payments between businesses.

The flow

How it works end to end

1
Buyer

Raise a purchase order & lock payment

Call POST /escrow/generate with the PO details as the task_description — supplier name, line items, agreed amount, delivery terms. Funds lock on XRPL. The supplier's wallet address is the escrow destination.

2
Supplier

Submit the invoice

When goods or services are delivered, the supplier calls POST /evaluate with the escrow_id and their invoice as the work field — plain text or structured JSON. Receipts and delivery confirmations can be attached.

3
Automatic

AI referee checks the invoice against the PO

The referee reads both the task spec (PO) and the submitted work (invoice). It checks: amounts match, supplier details are correct, line items correspond, no obvious duplication. Returns a PASS/FAIL verdict with a plain-English explanation.

4
Automatic

Payment released or supplier corrects

PASS → the referee releases payment on-chain to the supplier's wallet automatically. FAIL → the supplier sees the reason and can resubmit a corrected invoice (up to the attempt limit you set).

Code — Buyer

Creating the escrow at PO time

import httpx, secrets
from xrpl.clients import JsonRpcClient
from xrpl.models.transactions import Payment, EscrowCreate
from xrpl.wallet import Wallet
from xrpl.utils import xrp_to_drops
from xrpl.transaction import submit_and_wait

REFEREE  = "https://xrpl-referee.onrender.com"
PROTOCOL_WALLET = "rmcSrkpZ2i2kuvtCPeTVetee9SixP4djR"
XRPL_NODE = "https://s1.ripple.com:51234/"

buyer_wallet   = Wallet.from_seed("sYOUR_BUYER_SECRET")
supplier_wallet = "rSUPPLIER_WALLET_ADDRESS"
client = JsonRpcClient(XRPL_NODE)

# ── Pay 0.1 XRP protocol fee ─────────────────────────────────────────────
fee_tx = Payment(
    account=buyer_wallet.address,
    amount=xrp_to_drops(0.1),
    destination=PROTOCOL_WALLET,
)
fee_hash = submit_and_wait(fee_tx, client, buyer_wallet).result["hash"]

# ── Generate escrow parameters ───────────────────────────────────────────
escrow_id = f"INV-{secrets.token_hex(4).upper()}"

po_spec = """
Purchase Order PO-2024-0042
Supplier: Acme Design Ltd
Services: Website redesign — 5 pages, mobile responsive, delivered by 30 Jan 2025
Amount: 500 XRP
Payment terms: on delivery and AI verification of invoice
"""

params = httpx.post(f"{REFEREE}/escrow/generate", json={
    "escrow_id":        escrow_id,
    "fee_hash":         fee_hash,
    "buyer_name":       "Buyer Corp",
    "buyer_address":    buyer_wallet.address,
    "worker_address":   supplier_wallet,
    "task_description": po_spec,   # PO details become the referee's rubric
    "amount_xrp":       500,
    "cancel_after_hrs": 720,       # 30-day payment window
    "category":         "invoice",
    "max_submissions":  5,         # supplier gets 5 attempts to submit correct invoice
}).json()

# ── Submit EscrowCreate on XRPL ──────────────────────────────────────────
escrow_tx = EscrowCreate(
    account=buyer_wallet.address,
    destination=supplier_wallet,
    amount=xrp_to_drops(500),
    condition=params["condition"],
    finish_after=params["finish_after_ripple"],
    cancel_after=params["cancel_after_ripple"],
)
tx_hash = submit_and_wait(escrow_tx, client, buyer_wallet).result["hash"]

# ── Confirm with referee ─────────────────────────────────────────────────
httpx.post(f"{REFEREE}/escrow/{escrow_id}/confirm",
    json={"tx_hash": tx_hash}).raise_for_status()

print(f"Escrow created. Share escrow_id with supplier: {escrow_id}")
# Send escrow_id to supplier via email, webhook, or your existing system
Code — Supplier

Submitting the invoice for verification

import httpx

REFEREE   = "https://xrpl-referee.onrender.com"
ESCROW_ID = "INV-ABCD1234"   # received from buyer

# Build the invoice as structured text — the more detail, the better the verification
invoice = """
INVOICE
Invoice number: INV-2025-0099
Date: 28 January 2025
From: Acme Design Ltd | rSUPPLIER_WALLET_ADDRESS

Bill to: Buyer Corp

Services delivered:
- Homepage redesign (mobile responsive): ✓ delivered 20 Jan 2025
- About page redesign (mobile responsive): ✓ delivered 22 Jan 2025
- Services page redesign (mobile responsive): ✓ delivered 24 Jan 2025
- Contact page redesign (mobile responsive): ✓ delivered 26 Jan 2025
- Blog index redesign (mobile responsive): ✓ delivered 28 Jan 2025

Total: 500 XRP
Reference PO: PO-2024-0042
"""

result = httpx.post(f"{REFEREE}/evaluate", json={
    "escrow_id": ESCROW_ID,
    "work":      invoice,
    # Optionally attach evidence links — staging URL, delivery confirmation, etc.
    "evidence_links": ["https://staging.buyercorp.com"],
}, timeout=120).json()

verdict = result.get("verdict")
score   = result.get("score")
summary = result.get("summary")

print(f"Verdict: {verdict} ({score}/100)")
print(f"Reason:  {summary}")

if verdict == "PASS":
    print("Payment released to your wallet automatically.")
else:
    print("Please correct and resubmit. Reason above.")

Writing a good invoice spec: the more detail in the PO task description, the more precisely the referee can verify. Include supplier name, line items, amounts, and delivery terms. The referee will flag mismatches in any of these fields.

Verification

What the AI referee checks

  • Invoice amount matches the agreed PO amount
  • Supplier name and wallet address match the PO
  • Line items correspond to the services or goods specified
  • Delivery terms have been met (dates, quantities, scope)
  • Invoice number is present and the invoice appears original (not a duplicate)
  • Any attached evidence links support the claimed delivery

A FAIL verdict includes a plain-English explanation — the supplier knows exactly what to correct before resubmitting. The number of allowed resubmissions is set by the buyer at escrow creation (max_submissions).

OFAC screening is automatic. Both buyer and supplier wallets are checked against the US Treasury SDN sanctions list before the escrow is created. Sanctioned addresses are blocked from participating.

Currency

Pay in XRP or RLUSD

For invoice payments where price certainty matters, use RLUSD — Ripple's USD-pegged stablecoin on XRPL. Set currency: "RLUSD" and amount_rlusd instead of amount_xrp in the escrow generate call.

# Use RLUSD for stable invoice amounts
params = httpx.post(f"{REFEREE}/escrow/generate", json={
    "escrow_id":        escrow_id,
    "fee_hash":         fee_hash,
    "buyer_name":       "Buyer Corp",
    "buyer_address":    buyer_wallet.address,
    "worker_address":   supplier_wallet,
    "task_description": po_spec,
    "currency":         "RLUSD",
    "amount_rlusd":     500.00,    # $500 USD — stable, no price volatility
    "cancel_after_hrs": 720,
    "category":         "invoice",
}).json()
